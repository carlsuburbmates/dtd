# DTD Invariants and Constraints

These rules apply in every phase. A proposed feature that conflicts with one requires an explicit decision-register amendment before implementation.

## Commercial and user trust

1. Dog owners do not pay DTD to browse, match or contact trainers.
2. DTD charges no commission, transaction percentage, per-lead fee or per-introduction fee.
3. Monetisation is trainer-side flat subscriptions and finite sponsorship inventory.
4. Public copy must not imply a provider, action, verification, guarantee or live commercial state that evidence does not support.

## Matching and fairness

5. Behavioural and service fit is calculated without paid status.
6. Paid status may act only as the documented tiebreak inside the five-point comparable-fit band.
7. Safety, policy, suppression and eligibility gates outrank commercial priority.

## Acquisition and data authority

8. Persistent trainer inventory may originate only from first-party submission/claim, an owner-authorised official URL, or an explicitly approved official/licensed source.
9. ABR verifies statutory identity/status; it is not a trainer-discovery or service-quality source.
10. Gemini may structure facts from an already-lawful source. AI confidence, Search Grounding and Places/Maps content are not acquisition authority.
11. Every ingested profile carries source evidence, retrieval time, quality outcome and suppression checks. Trainers retain correction, claim and removal paths.
12. Credentials and private provider data never enter documentation, manifests or public evidence.

## Education boundary

13. The First Leash is a separate deployment and codebase. Main DTD owns directory, matching, trainer, enquiry and billing systems; First Leash owns education.
14. Cross-site handoff is static and query-free. Behaviour concerns, suburb, bite level, dossier text and other user data remain off the URL.
15. Main DTD may retain redirects and brand links, but not duplicate curriculum, education APIs or education-only assets.

## Operations and reliability

16. DTD is operated by one non-technical founder. Prefer bounded automation, low maintenance and exception-driven operations.
17. Every material workflow is assessed end to end: UI → API → persisted state → notification/fallback → `/ops`.
18. Mutating operator actions require authentication, confirmation, idempotency and an audit record. Financial actions fail closed.
19. Local code, deployment, provider configuration and live behavior are distinct evidence states. Never infer one from another.

## Documentation governance

20. Current, targeted and visionised states remain separate.
21. The decision register explains why; specifications define contracts; current state records evidence. README summarises but never creates authority.
22. Superseded product and process documents leave the active tree only after useful content is absorbed, then move to dated archives. Secrets registries must not be treated as product specifications.
